## Modbus 0x02 Illegal Data Address（GetPanelAdapterModelAsync 报错）
- 报错位置：ModbusRtuDataSource.cs:67 `ReadHoldingRegistersAsync(_slaveId, 3, 9)` → 读保持寄存器地址 3~11。
- 根因：Modbus Slave 只配置了 0/1/2 三个保持寄存器（对应三个计数），地址 3 往后未定义，从站拒绝 → 抛 Exception Code 2。
- 连带：① 代码请求 9 个寄存器但 regsStr 只有 7 个标签，数量不匹配；② PanelAdapterVm.Update() 的 catch 只 Debug.WriteLine，异常被吞，导致 PanelAdapter 静默空白（与"接好却刷不出"现象同源）。
- 解决：在 Slave 中补建 3~9（或 3~11）保持寄存器；或把读取范围改到从站真实存在的区间；并让 quantity 与标签数一致、对读取失败做降级缓存。

## PanelAdapter 闪动问题
- 根因：`PanelAdapterModels` 是 `List<PanelAdapterModel>`，每次 `Update()` 都 `PanelAdapterModels = data` 赋一个全新的 List，ItemsControl 视为 ItemsSource 整体重置，销毁并重建所有子控件 → 闪动。
- 修复：把 `List<PanelAdapterModel>` 改为 `ObservableCollection<PanelAdapterModel>`，保持集合实例不变，按索引逐个 `PanelAdapterModels[i] = data[i]` 更新（只 Raise Replace 通知，不重置），配合值相等判断跳过无变化项。
- 更彻底：把 `PanelAdapterModel` 从 record 改为带 INotifyPropertyChanged 的可变 class，直接改属性值，连 Replace 通知都不发，闪动最小。

## PanelAdapterVm.Update() ArgumentOutOfRangeException 崩溃
- 现象：Update() 中 `for (i<data.Count) PanelAdapterModels[i]...` 报 Index 越界（line 67）。
- 根因：`_panelAdapterModels` 初始化为 `new List<PanelAdapterModel>()`（空），Update() 直接按 `data.Count` 索引，但集合里一个元素都没有 → `PanelAdapterModels[0]` 越界。改用"可变 class + 按索引赋值"时漏掉了"先按 data.Count 对齐集合长度"这一步。
- 修法（三处）：① PanelAdapterVm 把 `List` 改成 `ObservableCollection<PanelAdapterModel>`（Add/Remove 才会通知 ItemsControl 渲染，否则即使填了数据卡片也不显示）；② Update() 开头加 null 守卫 + 长度对齐（Count>data.Count 删、Count<data.Count 加占位），再按索引原地改 ItemName/ItemValue；③ PanelAdapter.xaml 的绑定路径仍是旧的 `_itemValue`/`_itemNmae`（私有字段，且类名已改为 `ItemValue`/`ItemName`），必须改成 `{Binding ItemValue}` / `{Binding ItemName}`，否则修好崩溃后卡片文字依旧空白。

## PanelAdapter「高度不够 / 挤下去」布局问题
- 环境面板外层 `Border Height="200" Padding="10"`（MonitorAUserControl.xaml），内部 Grid 第一行 RowDefinition 曾误写 `Height="200"` 把 star 行空间吃光 → 改 `Auto` + 删空行后仍存在。
- 真正剩余原因：PanelAdapter 内部用 `WrapPanel`，换行由「实际宽度」决定。左栏窄时 7 卡折成多行 → 总高超过固定 200 → 底部被裁。
- 想保持 `Border Height="200"` 固定的解法：把 PanelAdapter 的 ItemsPanel 由 `WrapPanel` 改为 `UniformGrid Columns="4"`，强制一行 4 个 → 7 项恒为 2 行，高度确定，必能装进 200；并去掉卡片 `Border Width="90"` 让其在 4 列里均匀撑满。若用 WrapPanel 想固定行数则不可靠（受宽度影响）。

## ControlTemplate 内绑 GroupBox.Header 不显示
- 现象：GroupBox 的 ControlTemplate 里 `<TextBlock Text="{Binding Header}">` 不显示文字。
- 根因：在 ControlTemplate 内部，元素默认 DataContext 是「继承下来的 DataContext」（即父级 MonitorAViewModel），不是被模板化的 GroupBox 本身。所以 `{Binding Header}` 找的是 VM.Header（VM 上没有），自然为空。
- 修法：要绑被模板化控件自己的属性，必须用 `{TemplateBinding Header}` 或 `{Binding Header, RelativeSource={RelativeSource TemplatedParent}}`。这条规则对所有自定义控件模板都适用。
- 额外：模板里多个子元素（Polyline/Border/Ellipse/TextBlock/ContentPresenter）都默认落在 Grid 的 (0,0) 单元格相互叠加，靠 Margin + Horizontal/VerticalAlignment 定位到四角；空 `<ContentPresenter>` 没设 Grid 位置会盖在标题上，建议显式放内容区且给 Header 区独立定位。

- 分层原则：控件库不引用主工程 VM 类型，用通用类型（如 SeriesCollection）作接口，避免跨项目引用。

## 嵌入用户控件的标准规范（通用 SOP，可套用）
- 判定问题：「控件需要父级主动传进一个具体数据/参数吗？」
  - 否（只是把某 VM 对象整体展示）→ **消费型**：父级设 `DataContext="{Binding 某VM}"`，控件内部用普通 `{Binding 某属性}` 即可，控件本身不写任何接口代码。例：PanelAdapter（`DataContext="{Binding PanelAdapterVm}"`）。注意：`DataContext` 是 FrameworkElement 自带属性（.NET 框架给的"万能插槽"），**不是自定义 DP，不需要在父控件或子控件里定义任何 DP**。早期 MonitorAUserControl 上的 `PanelAdapterData` DP 属"接口型错误实现"（类型还注册成 PanelAdapter 控件本身），非消费型所需，已建议删除。消费型 DP 数量 = 0。
  - 是（有可配置输入，如图表数据/标题/阈值）→ **接口型**：① 控件后台定义 DependencyProperty 当插槽（如 `ChartSeries`）；② 控件内部子元素绑自身 DP 用 `{Binding X, RelativeSource={RelativeSource AncestorType=local:自身}}`；③ 父级 `<um:Xxx 属性="{Binding VM属性}"/>` 传值。例：LivePanelControl。
  - 都不是（只是占位把别的控件放进去）→ 直接写进 ContentPresenter，无需接口。
- 数据源头永远在 ViewModel（INotifyPropertyChanged），控件只管显示。
- 三条铁律：① 控件内部读「自己」的属性必用 RelativeSource AncestorType=自身；② 嵌进自定义模板控件（GroupBox 等）其 ContentPresenter 必须显式定位（Margin），否则盖住装饰/标题；③ 控件库绝不反引主工程类型（靠 DataContext 注入或通用类型 DP 接口实现解耦）。
