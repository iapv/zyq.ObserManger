## 项目：zyq.ObserManger（WPF 生产监控系统）
用户在搭一个 WPF 生产监控桌面程序，边学边做。

### 今日关键决策与约定
- 架构：主项目 `zyq.ObserManger`（WinExe, MVVM）引用控件库 `UserControlLibrary` / `UserControlMAinRouter`（WPF 类库）。
- 控件库只暴露 DependencyProperty，**绝不引用主项目、绝不访问数据库**。数据由主项目 ViewModel 通过 DataTemplate 桥接喂入。
- 页面切换用 `ContentControl Content={Binding CurrentView}` + `DataTemplate DataType={x:Type vm:xxxVm}` 做 ViewModel-First 路由。
- 用户控件显示系统时间：用 `DispatcherTimer`（Interval=1s）更新 DP；用 `HH:mm` 时一分钟才变一次（初学者易误以为"不走"，实为正常）。设计器预览不 tick，必须 F5 运行。
- 数字分格显示（机台总数等）：`ItemsControl` + `ItemTemplate`（红框 Border+TextBlock）+ `ItemsSource` 为字符数组；注意 ItemsControl 默认竖排，需 `ItemsPanelTemplate` 改成 Horizontal。

### 数据来源分层（用户提问"数据放哪"）

### 取数层方向决策（16:55 左右）
用户决定**用 Modbus 通信协议模拟取数**以贴近真实工控场景（生产监控系统上位机常用 Modbus 与 PLC/电表/传感器通信）。
- 关键架构：定义 `IMonitoringDataSource` 接口，ViewModel 只依赖接口；下挂 `MockDataSource`（写死/随机）与 `ModbusTcpDataSource`（NModbus 连 localhost 从站模拟器，读保持寄存器→映射字段）两个实现，靠配置/DI 切换。
- 无硬件也能练：跑一个 Modbus 从站模拟器（软件，localhost TCP），主项目当主站去读。
- 控件库仍不碰取数，只通过 DP 显示。

### Modbus RTU（RS485）实现（18:45 后）
- NModbus 3.0.83 核心包**无 SerialPortAdapter 类**（串口适配器在独立包 NModbus.Serial，但用户自实现了更轻量方案）。
- 自实现 `Services/SerialPortAdapter.cs` 实现 `IStreamResource`（包 SerialPort 的 Read/Write/Timeout/DiscardInBuffer/Dispose），`factory.CreateRtuMaster(adapter)` 创建 RTU 主站。
- `ReadHoldingRegistersAsync` 仅 3 参数重载（无 CancellationToken）。
- **关键 bug**：`SerialPortAdapter` 构造函数参数名写成 `_serialPort`，与私有字段同名 → `_serialPort = _serialPort` 自我赋值，字段恒为 null，运行报 `NullReferenceException`。修法：参数改名 `serialPort`，字段保持 `_serialPort`。
- 虚拟串口对 COM12<->COM13：Modbus Slave 占 COM12，则 C# 程序连 **COM13**。构造函数默认 `portName="COM13"`。
- VS 热重载（Edit and Continue）改构造函数/字段时局部变量显示失真（port 看似 null）并报 ENC0000；解法：Shift+F5 停调试 → Ctrl+Shift+B 重新生成 → F5。CS8618 提示可空字段未初始化，给 `= string.Empty` 默认值消除。
